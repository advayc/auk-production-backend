Transcript editor status

Status page, Nov 20, 2026. The transcript editor is the correctable-transcript flow: transcribe once, correct the words, align, review, preview, save. There are no audio players on this page on purpose: no verified output exists yet.

Not a finished feature. One real representative edit through actual GPU generation has not run yet. Everything below is code-level and alignment-level verification, not listening verification.

What changed (backend v0.6.0)

  • Accept-ASR-as-is spans now carry worker-registry-bound evidence, same as corrected spans. The worker verifies the MAC and still re-checks the cut segment against ASR; a mismatch fails closed.
  • Measured-timing transplants now compute the base-cut fit. They previously always failed closed.
  • The 0.5s segment duration floor is preserved: shorter selections are refused with explicit wider context options, never silently widened.
  • 534/534 CPU tests pass on the current tree (Linux, 2026-11-20), including the fail-closed gates.

What is measured

  • Forced alignment (pinned wav2vec2-base-960h) measures corrected words against the audio itself: 14/14 words on real speech on a Colab L4 run (mean uncalibrated fit 0.9054). That run exposed the two lifecycle gaps fixed above.
  • Manual audio-slice review remains the labeled fallback when alignment is not enough.

What is not verified

  • No audio has been generated for this new flow. The gaps fixed in v0.6.0 meant earlier runs could never reach generation on these paths.
  • Whole-sentence replacement still fails the strict speaker-similarity gate (12/12 attempts on the Oct 27 L4 run), so it correctly produces no output.
  • Nothing on this page has been listened to as a product verdict.

Evidence: github.com/advayc/auk-production-backend (v0.6.0) and backend/reports/77-STATUS_DETAIL_2026-11-20.md in that repo.

Transcript editor status

Status page, Nov 20, 2026. The transcript editor is the correctable-transcript flow: transcribe once, correct the words, align, review, preview, save. One explicit 2x-speed fixture now has a fresh v0.6.6 L4 generation, test save and final MP3 export. Listening quality remains unscored.

Not a finished feature. One fixture passes automatic checks, not broad reliability or listening approval. Quiet-source localized edits, multilingual and natural slurred-speech performance remain unresolved.

Current backend v0.6.6

  • Accept-ASR-as-is spans now carry worker-registry-bound evidence, same as corrected spans. The worker verifies the MAC and still re-checks the cut segment against ASR; a mismatch fails closed.
  • Measured-timing transplants now compute the base-cut fit. They previously always failed closed.
  • The 0.5s segment duration floor is preserved: shorter selections are refused with explicit wider context options, never silently widened.
  • 594/594 CPU tests pass on the current tree (Linux, 2026-11-20), including the fail-closed gates.

What is measured

  • Forced alignment (pinned wav2vec2-base-960h) measures corrected words against the audio itself: 14/14 words on real speech on a Colab L4 run (mean uncalibrated fit 0.9054). That run exposed the two lifecycle gaps fixed above.
  • Manual audio-slice review remains the labeled fallback when alignment is not enough.

Final output: MP3

The notebook now plays and downloads MP3 across edit paths. Final MP3 is mono 48 kHz, verified 320 kbps; internal 24 kHz WAV stays for lossless processing and QA. Resampling adds no source detail.

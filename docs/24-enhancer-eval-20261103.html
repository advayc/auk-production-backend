AuK voice enhancer - model selection record

Enhancer eval: AuK generative cleanup vs open-source baselines

20-clip corpus (10 VCTK speakers x 2 degradations: cafe noise at 10 dB SNR, reverb+noise hard). WER via faster-whisper base.en against clean-reference ASR transcripts; aligned ESTOI spot check; latency on the production L4. Run 2026-11-03. All 6 pipelines completed 20/20 clips.

Verdict: the AuK generative enhancer (the v0.5.0 backend default, 16 steps / guidance 1.0 / sway -1.0) is the strongest option tested. It beats every open-source model on both conditions on word accuracy, ties the server-default 32-step config (so the cheaper 16-step default stands), and its output spectrum tracks the clean reference. Only MossFormer2 clears the do-no-harm bar among the OSS models. Resemble's full enhance stage actively damages word accuracy and is disqualified. Update same night: a 10-speaker held-out expansion (eval-v2 below) narrows the win - AuK still leads pooled over 40 clips (0.175 vs 0.205 WER) but the paired tests are not significant, and MossFormer2 edges AuK on the hard reverb condition for the new speakers.

Pooled across all 40 clips (v1 + v2, per-clip paired): AuK 0.175, MossFormer2 0.205, raw input 0.301. Per-condition pooled: cafe 0.005 (AuK) vs 0.038 (MossFormer2); reverb-hard 0.346 vs 0.372. Paired per-clip AuK vs MossFormer2: 12 wins, 20 ties, 8 losses; sign test p=0.50, Wilcoxon p=0.38.

Honest read: the decisive v1 win does not fully replicate on untouched speakers. AuK remains clearly stronger on cafe noise (0.005 vs 0.038 pooled) and its aligned ESTOI on the hard v2 clips is far better (0.555 vs 0.138 - it reconstructs word-accurate but not sample-aligned speech, which the intrusive metric only partially credits). But on the hard reverb+noise condition with new speakers, MossFormer2 edges AuK on WER (0.377 vs 0.431), and over the pooled 40 clips the AuK lead (0.175 vs 0.205) is not statistically significant. Both pipelines beat doing nothing by a wide margin (input 0.301). The v2 reverb-hard clips are also simply harder (input WER 0.633 vs v1's 0.487), so part of the gap is corpus difficulty. Next lever for the hard condition: the backend's mastering layer (realignment + dry/wet blend), which the raw-server outputs here do not use.

On the hard condition AuK wins both WER and ESTOI outright. Its negative cafe ESTOI is a measurement artifact, not a quality signal: the raw server output carries small time-varying duration drift (about 60 ms lead at clip start) and intrusive metrics punish any generative reconstruction that is not sample-aligned, even when word accuracy is perfect. The backend pipeline removes exactly this drift (per-chunk length restore plus cross-correlation realignment, 2% cap), so backend-integrated output should score better than the raw numbers here.

Bandwidth

95% spectral rolloff, Hz. Clean reference 718. Raw input 1165-2725 (noise energy). AuK 726-832 - tracks the clean reference, removing the high-frequency noise floor. MossFormer2 708-946 similar. Resemble full enhance 1122-4648 (adds high-frequency hash). The AuK path outputs true 24 kHz audio; Adobe Enhance Speech is band-limited to about 9.5 kHz.

Against Adobe Enhance Speech

Adobe's published numbers (cleanvoice.ai independent benchmark): WER 17.1%, DNSMOS 3.08, speaker similarity 0.945, output band-limited near 9.5 kHz. Our AuK pooled WER of 13.0% is on this corpus, not Adobe's benchmark - the numbers are the same ballpark, not a superiority claim. A true head-to-head needs Adobe's output on these same 20 clips (pending reference clips, non-blocking). Structural advantages that hold without the head-to-head: full-band 24 kHz output vs ~9.5 kHz, and it rides the same AuK server the production backend already runs - no new infra and no new spend.

Method and caveats

Corpus. 10 VCTK speakers, each degraded two ways: cafe noise mixed at 10 dB SNR, and reverb+noise hard mix. Synthetically degraded, so the clean references are exact - real-world noise is the next step up.

Metrics. WER: faster-whisper base.en on each output vs the ASR transcript of the matching clean clip (inputs resampled to 16 kHz for ASR). ESTOI: pystoi extended at 48 kHz; the main table's ESTOI was computed without time alignment and read as directional only; the aligned spot check above is the reliable read. AuK outputs were scored as raw server output, without the backend's mastering layer (loudness, realignment, dry/wet blend).

Environment. Colab L4 (sm_8.9, 23 GB), audio.cpp v0.9.0 prebuilt (sha-pinned), AuK Base F32 + Qwen Q8_0 + VAE F32 GGUF, seed 42. AuK latency is estimated from the run window (~40 min for 40 inferences including an 11 GB model download and server start); per-clip server timing was not captured this run.

Failures kept in the record. DeepFilterNet3 needed a rust toolchain rebuild, a torchaudio compatibility shim, and tensor shape fixes. Resemble needed a no-deps install, a device-mismatch patch in its inference.py, and lambd ≤ 1.0. The full metrics pass needed CUDA 12 userland libs on LD_LIBRARY_PATH. The Colab kernel restarted mid-probe (pip installs lost, /content survived) and one browser lease idled out; both were recovered and rerun. Resemble's full enhance stage is disqualified on word accuracy (pooled WER 0.697 vs input 0.262).

Known worst case

Worst AuK result: speaker p304 reverb+noise hard, WER 1.000 - but the raw degraded input is also 1.000 on this clip (ASR loses it before any enhancement), so it is the corpus's hardest clip rather than an AuK regression. Note AuK-32 scores 1.25 there (more ASR insertions than reference words), one reason the 16-step default stands. Best OSS on that clip: Resemble denoise 0.375, MossFormer2 0.625.

Why the original fixtures failed: the fixtures, not the pipeline

Both original inputs are degraded corpus variants: custom-01 (vctk-p293_035-mic2) carries added noise at 25 dB SNR; custom-09 (vctk-p351_030-mic2) carries simulated room reverb. Production-equivalent ASR (faster-whisper small, beam 3) transcribes the input audio itself as “There is a lot of heroin in the boat.” (official transcript: “…heroin about.”) and “…Bill Gates of the theatre.” (official: “…of theatre.”), word-timestamp confirmed.

The raw clean versions of the same utterances fail the same check with the same mishearings - both are Northern Irish speakers whose pronunciation defeats the pinned ASR against the official transcript - so a same-utterance replacement was unwinnable. New clean utterances were chosen from the corpus’s fully clean subset (no added noise, no added room simulation); both pass fixture-QA word-for-word and neither collides with any existing W4 fixture.

The pipeline preserved the input content faithfully - verified word-for-word through the v035 transplant - across 6 generation seeds per case. The exact-match gate was never relaxed; the fixtures were swapped instead.

The two backend fixes

  • v035 (custom): the style-scope prosody transplant guard read the wrong plan field, so the transplant never engaged and raw vendor output was used - the W3 speaker-identity-collapse path. The guard now reads plan.expected_transcript; the transplant engages on every style-scope case. Commit eb9788d.
  • v036 (humming): (a) ASR word spans under-cover final syllable tails by ~0.2s, so surgical hum excision clipped the last syllable (“Crystal.” → “Chris”); excision now ends 0.25s after the word end, capped at the next word start. (b) comb_notch overlap-add zero-pad fixes the zeroed clip tail and full-scale end click present in all v034 outputs. Commits 7f183de, 39a8e67.
  • Both fixes run under the pinned runner (per-module SHA-256 checks) and are pushed to GitHub (commit 6678826).
